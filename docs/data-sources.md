読めなかった、または要約しかできなかったものは **「要目視(ユーザー)」** と書く。推測は「推測」と明記する。

### 1.2 利用条件(coment.html)
- 「コンテンツは、権利表記がない限り『公共データ利用規約(第1.0版)』に準拠した利用条件の下で、利用することができます」。
- 適用外: 組織や事業のシンボルマーク・ロゴ・キャラクターデザイン、別の利用ルールを明示しているコンテンツ、気象業務法 第17条第1項(予報業務の許可)・第23条(警報の制限)に基づく利用制約のあるページ。
- 生物季節観測のページ(index.html)とダウンロードページには、別の利用ルール・利用条件の記述はなかった(「気象庁ホームページについて」へのリンクのみ)。
- **自動巡回(定期的な機械的収集)を控えるよう求める記述は、今回読んだ 4 ページの中には見つからなかった。** 付録 B の「自動巡回は控える」は、今回読んだ範囲では裏付けを確認できていない(別のページにある可能性。**要目視(ユーザー)**)。段階13 では作業指示書どおり「一度だけの取得」に限る。

### 1.3 公共データ利用規約(第1.0版)の要点
令和6年7月5日(2024-07-05)制定。
- 1.: 「複製、公衆送信、翻訳・変形等の翻案等、自由に利用できます」「商用利用も可能です」。
- 数値データや簡単な表・グラフは著作権の保護の対象ではなく、このルールの適用もなく自由に利用できる(道具の要約)。
- 1.1.1 出典の記載。例「出典:D庁ウェブサイト(当該ページのURL)、PDL1.0(規約原文ページのURL)」。
- 1.1.2 編集・加工したときは、出典とは別に、加工したことと、その主体を記載する。例「『○○動向調査』(D庁)(当該ページのURL)を加工して作成」。加工した情報を、国などが作成した未加工の情報であるかのように公表・利用してはならない。
- 1.2 第三者の権利を含むものは利用者の責任で確認・許諾。1.6 免責。1.7.3 CC BY 4.0 と互換。

### 1.4 public の GitHub リポジトリに置いてよいか
- 規約の文面(1. の「公衆送信」「自由に利用」「商用利用も可能」、1.7.3 の CC BY 互換)からは、**出典と加工の記載をすれば、加工したデータをインターネットで公開してよいと読める**。
- ただし、(1) ページは要約の道具を通してしか読めていない、(2) 「再配布」の語は規約にない(公衆送信に含まれると読むのは解釈)、(3) フォーマットの PDF と、付録 B にある「自動巡回は控える」の記述の場所を確認できていない。
- → 作業指示書の既定の判断(「はっきり確認できなかったデータは置かない」「迷ったら置かない」)に従い、**段階13 では `data/jma_phenology/raw/` と `normalized.csv` を `.gitignore` にし、リポジトリには置かない**(判断 D-03)。人が規約を目視して問題ないと判断したら、`.gitignore` の2行を外せば置ける。

### 2.2 利用条件
- 「You may only use the free API services for non-commercial purposes.」非商用の定義は Creative Commons の解釈による。例: 購読・広告のない個人・非営利のサイトやアプリ、個人のホームオートメーション、公的機関の公開研究、教育。
- 無料枠の上限: **600 calls/分、5,000 calls/時、10,000 calls/日、300,000 calls/月**(pricing によれば月の上限は現在は強制していない)。上限は IP アドレスとアプリケーションごと。濫用は予告なく遮断されうる。
- 「The data obtained through the API is provided under the terms of the CC-BY 4.0 licence.」
- キャッシュ・保存・再配布・加工データの公開について、無料枠の規約には記述がなかった(禁止の記述もない)。
- 規約の日付の記載なし(© 2022-2026、変更履歴は GitHub)。
- **1 call の数え方**(pricing の FAQ): 「Typically, one API call corresponds to one HTTP API request.」ただし「Requests for data covering more than 10 weather variables」または「extending over a period of more than 2 weeks for a single location are considered multiple API calls」で、端数で数える(例: 2 週・15 変数で 1.5 call、4 週で 3.0 call)。
  → **長い期間の過去データの問い合わせは 1 リクエストでも複数 call と数えられる**。正確な式は書かれていない(例から `変数の数/10 × 週数/2` に近いと読めるが**推測**。1 変数のときの下限が 1 かどうかも未確認)。見積もりは `docs/validation-plan.md` で安全側に計算する。

### 2.3 出典表示
- 既存(README): *Weather data by Open-Meteo.com (https://open-meteo.com/), licensed under CC BY 4.0*。
- 過去データ(Historical API)の仕様ページには、追加で「Generated using Copernicus Climate Change Service information 2022.」の表示が求められている(ERA5 などの再解析データの帰属)。引用例: Zippenfenig, P. (2023). Open-Meteo.com Weather API. Zenodo. https://doi.org/10.5281/ZENODO.7970649。ERA5・ERA5-Land にも個別の引用がある(文言は仕様ページで**要目視**)。
- → 段階14 で過去データを使った結果を公開するときは、上の2つを両方書く。

### 2.4 標高(`elevation`)の扱い(段階14 の前提)
- 仕様(Historical API。予報 API にも同じ引数がある想定だが、**予報 API のページは今回読んでいない = 未確認**): 「Per default, a 90 meter digital elevation model is used.」標高は統計的ダウンスケーリングに使われる。手で指定でき(例: 山頂に合わせる)、複数地点はカンマ区切り。「If &elevation=nan is specified, downscaling will be disabled and the API uses the average grid-cell height.」
- v0 は `elevation` を渡していない(`docs/stage13-report.md` フェーズ 0-4)。したがって v0 の気温は、Open-Meteo が 90 m の標高データから決めた、問い合わせ座標付近の標高のもの(応答の `elevation`: 高尾山 598 m、谷川岳 1920 m、赤岳 2599 m)。
- エンドポイント: `https://archive-api.open-meteo.com/v1/archive`。`latitude`・`longitude`・`start_date`・`end_date`(yyyy-mm-dd)が必須。日別の変数を使うときは `timezone` が必須。`temperature_2m_min` は日別で使える。
- 再解析のモデル: 既定は「Best match」(IFS HRES・ERA5・ERA5-Land を組み合わせる)。ERA5 は 1940年〜(0.25°、約 25 km、5 日遅れ)、ERA5-Land は 1950年〜(0.1°、約 11 km、5 日遅れ)、ECMWF IFS は 2017年〜(9 km、遅れなし)。モデルを選ぶ引数名はページから読み取れなかった(**要目視**)。
