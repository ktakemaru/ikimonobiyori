# イキモノビヨリ 設計(ネイチャーガイド仕様)

この文書は、設計書「イキモノビヨリ 設計書(ネイチャーガイド仕様)」の要点を、このリポジトリの文書として整えたもの(段階13 の作業指示書の付録 A の写しをもとにする。付録 A にない事実は足していない)。
段の名前・型の割り当ては**案**で、段階14 以降の作業で確かめる。v0(紅葉・野鳥)の挙動は、この文書によって変わらない。

関連: データ源の利用条件は `docs/data-sources.md`、紅葉の答え合わせの手順は `docs/validation-plan.md`、v0 の調査と出典は `docs/ikimonobiyori-research.md`。

## 1. 役割の分担(2026-10-21 決定)

| ビヨリ | 受け持つもの |
|---|---|
| イキモノビヨリ | 生き物(植物・動物・菌類。光るキノコを含む)の専門家。ガイドの「語りの材料」を構造化して出す |
| ヤマビヨリ | 気象の現象(山の天気・雲海・霧氷) |
| ホシビヨリ | 天文の現象(月明かり・天の川) |
| ビヨリコンシェル | ネイチャーガイドとして語る窓口(方針案。未確定) |

イキモノビヨリのコードはこのリポジトリの中に閉じる。窓口(biyori-hub)の変更は、この設計の範囲ではしない。

## 2. 共通の枠組み

**見どころ = 対象 × 場所 × 時期 × その日の条件。**

提案の形式は `biyori-proposal/1` のまま変えない。

| 考え方 | 提案の項目 |
|---|---|
| 段階 | `phenology_stage` |
| 確からしさ | `band` と `validated` |
| 根拠 | `evidence` |
| 配慮 | `care` |

## 3. 時期の5つの型(`timing_type`)

| 型 | 時期を決めるもの | 予測・判定 | 対象の例 | band の上限 |
|---|---|---|---|---|
| `temperature`(気温型) | 気温の積み重ね | 気温モデル+標高補正 | 紅葉、いちょう、桜、梅、ホタル(天然) | 検証前は maybe、検証後は go |
| `calendar`(暦型) | 毎年ほぼ同じ時期 | 例年の時期+小さな補正 | 彼岸花、タカの渡り、夏鳥・冬鳥の到着、光るキノコ | 例年値に出典があれば go |
| `managed`(管理型) | 人の管理(種まき・放流) | 名所ごとの例年+公式の開花情報。気温モデルは使わない | ひまわり、コスモス、菜の花、ネモフィラ、放流地のホタル | 今年の公式情報を人が確認したときだけ go |
| `frequency`(記録頻度型) | 場所×週の過去の観察記録 | 相対頻度(今の野鳥の方式) | 野鳥 | 検証前は maybe |
| `episodic`(突発型) | プランクトンの増殖、迷鳥など | 予測しない。最近の記録と公式の発生情報 | 夜光虫、珍鳥、ホタルイカの身投げ | 常に maybe まで |

型は名所カタログの各件に持たせる(同じ対象でも名所によって型が違うことがある。例: ホタルは天然なら temperature、放流地なら managed)。
プロファイルにも対象の既定の型として `timing_type` を持たせる(段階13 で項目を追加。v0 の判定には使わない)。

## 4. 対象別の仕様(段階の名前は案)

| 対象 | 型 | 段階 | 時期の根拠 | その日の条件 | 配慮 |
|---|---|---|---|---|---|
| 紅葉・いちょう | temperature | 色づき前/色づき始め/見ごろ/落葉始め | 日最低気温の積み重ね。見る場所の標高で補正。気象庁の紅(黄)葉日で検証 | 晴れ | 混雑、駐車場 |
| 桜・梅 | temperature | つぼみ/開花/満開/散り始め | 春の気温の積算。気象庁の開花日・満開日で検証 | 晴れ、風 | 混雑 |
| 彼岸花 | calendar | つぼみ/開花/見ごろ/見ごろ過ぎ | 例年の時期(公式)+夏の暑さによる遅れ(要出典) | 晴れ | 花を踏まない |
| ひまわり・コスモス・菜の花・ネモフィラ | managed | 開花前/咲き始め/見ごろ/終盤 | 名所ごとの例年+今年の公式情報 | 晴れ | 畑に入らない、開園時間 |
| 野鳥 | frequency(渡りは calendar) | なし(見つけやすさ) | 場所×週の過去の記録 | 早朝、天気、渡りは風向き | 巣に近づかない、位置は area_10km、餌付けしない |
| ホタル | temperature(放流地は managed) | 発生前/飛び始め/最盛期/終盤 | 名所の例年+春の気温による補正(逗子市の発生予測と同じ考え方) | 日没後、蒸し暑く風が弱い、雨の直後、月明かりが少ない | ライト・フラッシュを使わない、採集しない、生息地は位置を粗く |
| 夜光虫 | episodic | 発生情報なし/最近の発生情報あり | 予測しない。最近の記録と県の水産試験場の赤潮・海況情報 | 新月期、波が穏やか、夜間 | 夜の海の安全 |
| ホタルイカ | calendar+episodic | 季節前/季節中(身投げは突発) | 例年の漁期(要出典)+公式の情報 | 新月前後、夜明け前 | 捕獲のルール、夜の海の安全 |
| 光るキノコ | calendar | 季節前/季節中 | 例年の時期(要出典)+雨の後 | 雨の後、夜間 | 採取しない、夜の山道の安全 |

## 5. 名所カタログ

### 5.1 1件の形(案)

```yaml
- id: kouyou-0001
  name: 〇〇渓谷
  subjects: [autumn_leaves]
  timing_type: temperature
  species: [いろはかえで, ぶな]
  kind: point                     # point / area / river / coast
  point: {lat: ..., lon: ..., elevation_m: 900}   # 見る場所の標高(山頂ではない)
  location_precision: exact       # exact / area_1km / area_10km
  typical_window: {start: "11-01", end: "11-15", source_url: "..."}
  official_status_url: "..."      # 今年の状況の公式ページ(人が見る)
  description: "..."              # 人が承認した短い解説(出典つき)
  access_notes: "..."
  manners: [...]
  site_ref: yamabiyori:m012
  status: approved                # candidate / approved / retired
  approved_at: 2026-10-21
  sources: [...]
```

スキーマと検査器の実装は段階13 フェーズ 2(`ikimonobiyori/schemas/site-catalog.schema.json`、`python -m ikimonobiyori.catalog check`)。

### 5.2 承認の流れ
1. Claude Code が公式ページを読んで `candidate` を作る(出典の URL 必須)。
2. ユーザーが `approved` にする。
3. 提案に使うのは `approved` だけ。
4. 閉鎖・立入禁止になったものは `retired` にする(削除しない)。

### 5.3 既存の 76 地点との関係
`ikimonobiyori/data/sites.yaml`(山の 76 地点)は残し、v0 はこれまでどおり 76 地点を使う。カタログは段階14 で 76 地点と並べて動かす(段階計画)。

## 6. 検証の方針
- `go` を出せるのは、答え合わせを通ったプロファイル(`validated: true`)だけ。
- 気温型は気象庁の生物季節観測(2021年からは 6種目9現象: うめ開花、さくら開花・満開、あじさい開花、すすき開花、いちょう黄葉・落葉、かえで紅葉・落葉)で答え合わせする。
- 合格基準は、結果を見る前に決める。結果を見てから基準を動かさない。
- 気象官署は平地の都市部で、標本木は1本。山の名所に当てはめるには、見る場所の標高で補正する。
- 動物の答え合わせの候補(段階16・17): 気象庁の累年表には動物の記録もある(ほたる初見 024、さしば南下初見 106 など。2020 年まで)。
