## 評価表

| # | 条件 |
|---|---|
| R1 | 冒頭の1〜2文で、全体の結論(今が見頃か、まだ早いか、どこが近いか)を言う |
| R2 | 指定の地域(例: 神奈川)の候補を**3件以上**出す。地域に合わない候補は、県外と明示して分ける |
| R3 | 各候補に、**今の状態**(青葉・色づき始め・見頃・見頃過ぎ、花なら見頃前・見頃 など)と**その日付**と**出所**を書く。分からなければ「今の状態は分からない」と書いたうえで、例年の時期で出す |
| R4 | 各候補(番号つきのおすすめ・「ほかの候補」など、答えに名前を挙げて勧める名所のすべて)に、**例年の見頃**を書く。野鳥は「例年の見頃」の代わりに「**この時期に見られる鳥**」(出典つき)を書く。**例年の見頃(野鳥はこの時期に見られる鳥)が分からない候補は、「例年の時期は分かりません」と明言し、代わりに今年の行事の期間か、昨年(前の年)の記録を書けば、R4 を満たす。** 分からないことを理由に、候補を答えから外さない。(今年の行事も昨年の記録も、答えの材料にない候補は、「例年の時期は分かりません」の明言だけで R4 を満たす。) |
| R5 | 各候補に、**なぜそこか**(近い・今いちばん進んでいる・これから進む・行事がある など)を一言 |
| R6 | 該当があれば「避けたほうがよい場所(まだ早い・終わった)」と、別の目的での代わり(例: 菊花展)を出す |
| R7 | 確かさの補足(いつ時点か、公式か紹介サイトか、去年の情報か)を短く出す。**止める理由にはしない** |
| R8 | 答えの末尾に質問を付けない(好み・優先・選択を尋ねない。段階57 第13部。本人の指示 2026-11-07)。例外は、対象・場所・日付のどれも特定できず答えが作れないときの聞き返しだけ。できることの案内は質問の形にしない |
| R9 | 出典の URL を最後に並べる |
| R10 | 次の言い方が**1つも出ない**: 「材料がない」「情報がない」「おすすめを出せません」「使える期限を過ぎている(ので使わない)」「更新は私からは始めません」「! を付けて」「実行してください」「承認してください」「集めた事実だけを並べます」、内部用語(snapshot、status_log、proposal、band、max_age_h、pending、台帳 など)、作業の経過(「検査が通ったので」「答えを出します」「あとは答えを書くだけです」「今回は取りに行っていません」など)、開発・作業の言葉(「テスト」「コード」「作業メモ」「記録済み」「スキル」「コマンド」など) |
| R11 | スマホで読める長さ(目安 1,500字以内。字数で測る) |

## 追加の合格基準(段階H9・H10・段階37・段階38)

| # | 条件 |
|---|---|
| A1 | 答えの末尾の「○/○ に ○○ を読み直し、新しい記録が N件増えました」(または「読みに行きましたが、新しい情報は取れませんでした」)は、この回の記録の結果(ページごとの、本当に増えた新しい記録の数)と一致する。新しい記録が 0 件のページを「読み直しました」と書かない |
| A2 | 野鳥: 神奈川の探鳥地を3件以上。各候補に「この時期に見られる鳥」(出典つき)。「例年の見頃」の語がない。対象の日に休みの名所は、休みを言い切る |
| A3 | 状態の日付が古い名所は読み直している(読めなければ「読みに行きましたが、新しい情報は取れませんでした」と書いている)。例年の時期と今年の行事が区別されている(今年の行事の期間を「例年の見頃」と書かない) |
| A4 | 野鳥で、iNaturalist の集計が新しければ取り直していない(呼び出しの記録 `calls.json` の `inat_refresh` が `skipped: fresh`)。古い・対象の日が期間外なら取り直している(1 回の質問につき 10 リクエストまで)。段階38: 単体の実行では自前の上限の下で(記録 `netlog/requests.jsonl`)、ハブから呼ばれたときは計測フックの下で取り直す。上限に収まらない公園は古い集計を日付つきで使う |
| A5 | 段階38: 野鳥の候補ごとに、その公園で見られる鳥の名前と、なぜ今か(最近の記録・この時期に多い など)を書く。一年中いる鳥(トビ・ヒヨドリ・ハシブトガラスなど)が上位を占めない。内陸の公園に海の鳥(ウミネコ・イソヒヨドリなど)が上位に出ない |
| A6 | 段階38: 「HTMLにして」「写真つきで」と頼まれたとき、公園ごとの節に、その公園の鳥が写真つきで並ぶ(写真が付いた鳥が公園ごとに2種以上)。各鳥に、なぜ今か。撮影者名・ライセンス・「写真は種の代表写真で、その公園で撮られたものではありません」の1文がある |
| A7 | 段階38: 利用者への返事は、答えの本文と(ページを作ったときは)ページの場所の1行だけ。「今回の作業で実行したこと」「テスト」「コード」「リポジトリ」「追跡ファイル」「保存先」など、作業・開発の説明がない |

## ページ用の基準 P1〜P6(段階39。Artifact・HTML・ページを求められた質問に足して使う)
| 番号 | 基準 |
|---|---|
| P1 | Artifact・ページの依頼で、**イラスト(手描きの SVG)が出ない**。鳥・花のカードは写真、取れなかった種は「名前だけの行」(枠にしない)。撮影者・ライセンス・元ページのクレジットが付く。 |
| P2 | ページの大きさが、重複を除いて 2MB 以下(超えたら理由)。同じ種の写真が重複して埋め込まれない。 |
| P3 | 結論・順位が先頭にある。次の質問は末尾に 1 つだけ。 |
| P4 | 鳥・花は、場所の環境に合う。古い記録(7 日を超える)を「最近」と書かない。10 年以上前の記録を根拠にしない。まれな種をおすすめに入れない。 |
| P5 | 答えに内部の言葉・作業メモ・検査やテストの報告がない(全質問)。全経路で検査を通っている(検査を飛ばしていない)。 |
| P6 | 候補が 3 件以上で、聞き返しだけで終わらない。出どころ・日付・確度がある。野草は「例年の時期の目安」と明記し、採取・踏み荒らしの注意がある。 |

## 段階51の追加（2026-11-06 の試用で見つかった5点。facts の lines.answer_rules が stage51 のときに検査器が当てる）

- **A1 の読み替え**: 上の A1（答えの末尾の「読み直し、新しい記録が N件増えました」）は、段階51で**答えに書かない**ことにした。作業の報告（読みに行った・記録が増えた・取れなかった）は答えの外に書く。答えに書いてよい取得の結果は、読めなかったページを利用者が自分で開く 1 行（`lines.open_urls`）だけ。印のない古い形の facts は従来どおり（既存のテストの期待値は変えない）。
- **B1**: 冒頭の要約は「今回のおすすめ」の候補から書く。冒頭に書いた場所の種類（庭園・菊・野鳥など）と名前が、おすすめの候補にあること（`lead_mismatch`）。
- **B2**: iNaturalist の記録に基づく文には「公式ではありません」を添え、「一年の平均より多い」など傾向を言うときは、公園そのものでなく神奈川県などの範囲の傾向であることを書く（`inat_unlabeled`・`inat_scope_missing`）。
- **B3**: 本文で使った現況の事実の出典 URL と、iNaturalist のサイトを、出典の一覧に漏れなく出す（`source_missing`）。
- **B4**: 見込みを言い切らない（「見ごろに入る時期です」は不可。「入っている可能性があります」）。公式の文は丸ごと転載せず、状態の見出し（「◎ 真っ盛り」など）だけ原文のまま、ほかは短くまとめる（`assertive_forecast`・`long_quote`）。
