## 3. 第2部: 「ネイチャーガイドの知識の層」の設計

### 3-1. 何を蓄えるか

開花・野鳥・高山植物の**現況**ではなく、**ガイドが伝えたい知識**。次の分類で、地域・季節ごとに整理する（網羅しなくてよい。分類は拡張できる）。

| 分類 | 例 |
|---|---|
| 季節の仕組み | 紅葉が起きる条件（気温差・日照・水分）、標高で見頃がずれる、気温が8℃前後を下回ってから約3〜4週間後が見頃の目安（奥多摩の観察記録） |
| 場所ごとの見頃の流れ | 箱根の紅葉は高いところ（芦ノ湖周辺）から下り、最後は箱根湯本 |
| 出会い方・歩き方 | 混雑する山頂を避け、少し奥の「もみじ台」「一丁平」へ。朝夕・風・双眼鏡の使い方 |
| 痕跡・暮らし | リスの食痕「エビフライ」（マツの実）、シカの食害でお花畑が変わる、冬の「シモバシラ」（霜柱） |
| 地形・地質・火山 | 箱根火山の生い立ち、氷河地形のカール、蛇紋岩の登山道 |
| 保全・マナー | 盗掘と登山道外への踏み外し、外来種、えさをやらない、ゴミ |
| 安全 | クマ、スズメバチ、カエンタケ、日没の早さと下山時刻、冬の凍結、火山ガス |
| 名前・歴史・文化 | 名前の由来、地名、山岳信仰、むかし道 |
| 夜・天気・自然現象 | 夜の虫、星空、霧・雲海、季節の音 |
| シーズンの目安 | 開館・営業・バスの終了（例: 尾瀬は10月下旬、上高地は11/15、八島は10月末） |

### 3-2. 知識カードの形（1枚＝1つの事実のまとまり）

- 項目: **題**（短く）／**分類**／**場所**（施設・エリア・山域。座標または既存の名所との対応）／**事実**（短い箇条。月、標高、数値、種名、因果。**原文の文章は写さず、自分の言葉で書く**。最大5項目、1項目は60字以内）／**条件**（季節、標高、年に依存するか。年に依存する事実は年を明記）／**出典**（施設名、刊行物名、号、発行年月、URL、確認日）／**確度**（施設の観察記録／公的資料／施設の解説／紹介）／**権利メモ**（出典の利用条件の要約と、扱い: 事実のみ）／**答えでの出し方**（「ガイドの目」として1〜2行）。
- **文章・図・写真を写さない。** 事実（月・数値・種名・因果の短い言い方）だけを、出典つきで書く。表現そのものを使わない。引用符で原文を残さない。
- **今年の現況と混ぜない。** 現況は日付つきの別の仕組み。知識カードは「年によらない知識」と「年に依存する知識（年つき）」に区別する。

### 3-3. 保存場所（権利への配慮）

- ikimonobiyori のリポジトリは**公開**。知識カードの**本体は、リポジトリの外のデータ置き場**（IKIMONOBIYORI_DATA_DIR など、既存の仕組み）に置く。リポジトリには、**スキーマ、読み込みのコード、テスト用の合成カード**だけを置く。
- 出典の規約が厳しい施設（例: 高尾・御岳・奥多摩は、ウェブサイトポリシーが無許可利用・無断の複製・転用を禁じる）のカードは、**事実のみ・自分の言葉・出典明記**を徹底し、リポジトリに入れない。許可を得られたら、扱いを見直す（問い合わせは本人が行う）。
- 公式の資料でも、東京都環境局などの行政の資料は、各サイトのポリシー（引用・出典明記・二次利用の条件）を権利メモに書く。確認できなければ「未確認」と書き、事実のみとする。

### 3-4. コマンドとテスト

- `ask knowledge add|list|search|show`（名前は既存の体系に合わせてよい）を作り、場所・季節・分類で探せるようにする。
- テストを足す（合成データ、通信なし）: スキーマの検証（事実は最大5項目・60字以内、出典と確度が必須、年に依存する事実には年が必須）／原文のような長い文を拒否する／リポジトリ内に本物のカードが入らないこと。

## 6-2. 第6部（最初に実行）: サイト構造が決まっていないサイトと、PDF の本文の読み取り（通信あり。最大200回）

背景（本人の指摘 2026-11-07）: ビジターセンターなどの Web は、階層構造が決まっておらず、情報が **PDF** として蓄えられているケースが多い。HTML を読むだけでなく、**PDF の中身も読む**。チャット側の確認では、テキストの PDF（奥多摩の季刊誌、東京都レンジャーニュース、八島の「今週の八島湿原」、箱根四季だより、尾瀬情報）は本文が取れたが、**縦書きが1文字ずつ改行されて出る**（尾瀬情報）、段組や図中の文字の順序が乱れる、**画像だけ・図だけの PDF は数字しか取れない**（環境省の VC.pdf）といった差があった。Claude Code の環境では、八島の PDF が「本文が読めず」だった。

### 6-2-1. サイトの構造を辿って、PDF を見つける

1. 起点（施設の公式サイトのトップ、最新情報ページ）から、**同じサイト内のリンクを深さ3まで**辿る（外部サイトへは出ない。ただし、同じ運営主体の文書置き場、例: wp-content/uploads、自治体の documents/files は可）。**優先するリンク**: 「ダウンロード」「刊行物」「季刊誌」「広報」「だより」「お便り」「自然情報」「観察記録」「レンジャーニュース」「セルフガイド」「資料」「アーカイブ」「過去の」、および拡張子 .pdf。一覧のページ送り（「次へ」）も辿る。
2. **サイトマップ**（sitemap.xml、robots.txt の Sitemap の記載）があれば使う。
3. 検索で補う: 「site:ドメイン filetype:pdf」に年（2026・令和8年）を入れて検索する（検索手段がある場合）。
4. 見つけた PDF を**発行物台帳**に記録する（データ置き場）: 施設／題／号・発行年月／URL／形式／取得日／**読み取りの状況**（読めた・一部・読めない・画像のみ）／最終確認日。**最新号の判定**は、ファイル名・URL の日付、本文中の日付、一覧の並びから、年つきで決める（古い号を最新として扱わない）。
5. robots.txt で拒否されたパスは取得しない。規約の記載は、規約メモに短く記録する。

### 6-2-2. PDF の本文を読む（上から順に試し、読めた最初の方法を使う）

- **方法 a**: `web-fetch` エージェント経由で PDF の URL を取得する（テキストの PDF なら、本文が返ることが多い）。
- **方法 b**: a で読めないとき、PDF を**リポジトリの外の一時フォルダ**にダウンロードし、Read ツール（ページ指定。1回に最大10ページ、1つの PDF につき最大20ページ）で読む（画像のみ・複雑なレイアウトにも対応できる）。ダウンロードが権限で拒否されたら、**回避しない**（c に進む）。使い終わったら、一時ファイルを削除する（今回自分が作ったものの取り消しなので許可）。
- **方法 c**（承認欄が「あり」のときだけ）: pdfminer.six でテキストを抽出する。
- **方法 d**: それでも読めなければ、「PDF 未読」と記録し（URL・理由）、カードや現況は作らない（チャット側で読んで事実を渡す分担にできる）。
- どの方法で読めたかを、発行物台帳に記録する。

### 6-2-3. 読み取りの品質への対策

1. **縦書きが1文字ずつ改行される**PDF（例: 尾瀬情報）: 1行1文字の並びを検出し、連結して読む。連結しても意味が通らなければ、その部分は使わない。
2. **段組・図中の文字・表**: 順序が乱れやすい。**月・数値・種名は、本文の文脈で確かめられるものだけ**を事実にする。図の注記や表の数値は、確信が持てなければ事実にしない。
3. **画像だけ・図だけの PDF**（地図、一覧の図）: 数字しか取れないことがある。方法 b で、該当ページを読めるか試す。読めなければ「PDF 未読（画像）」。
4. 事実には、**PDF 上のページ番号**を記録する（文章は記録しない）。再確認できるようにするため。

### 6-2-4. 全文を保存しない

- PDF の本文テキストは、**事実を取り出したら破棄する**。保存するのは、発行物台帳（メタデータ）、再取得の判定用の内容のハッシュ、取り出した事実（知識カード、現況）だけ。PDF ファイルも、リポジトリ内に置かない。

### 6-2-5. PDF の現況情報

## 6-3. 第7部: 質問の意図の分類と、知識を先にする答えの型（別 commit。通信あり。最大100回）

背景（本人の指摘 2026-11-07、「冬桜」の会話）: 「冬桜について教えて」「冬桜と寒桜の違いを教えて」「山桜とか豆桜というのもあるんだ」「今見られる桜ってある?」の4問で、**ネイチャーガイドのような返事を期待していたが、どの答えも見頃と場所が中心**だった。

1. **質問の意図の分類**: 次のいずれかに分類する（複数にまたがる場合は、主たる意図を決める）。
   - 知識（「〜について教えて」「〜とは」「〜というのもあるんだ」など、ものごとへの興味）
   - 違い・比較（「〜と〜の違い」）
   - 場所・時期（「どこで」「いつ」）
   - 今の状況（「今見られる」「〜はどう?」）
   - 計画（「行きたい」「おすすめ」）
2. **答えの型**:
   - **知識・違い・比較**: 「どんなもの」→「似たものとの違い」→「見分け方・出会い方」→「いつ・どこで見られるか（最後に短く）」→「ガイドの目（保全・マナー・安全。該当するとき）」の順にする。**名所の一覧を主にしない。**質問が場所・時期を聞いていないときは、場所と時期は最後の1〜2行にとどめる。
   - **場所・時期・今の状況・計画**: これまでの計画（`ask plan`）の型。
3. **知識の出どころ**: 優先順は、研究機関（例: 森林総合研究所 多摩森林科学園）、国・自治体の解説（林野庁、環境省、自治体の名勝・天然記念物の案内）、ビジターセンター・植物園・博物館、そのあとに紹介サイト（公式でないことを添える）。知識カード（第2〜3部）があれば優先する。**ないときは、その場で検索・取得し**（1回の質問につき最大8ページ）、事実を知識カードの形で（仮の扱いで）データ置き場に記録してから使う（記録のない事実は書かない）。
4. **「名所の一覧に入っていないので答えられません」を書かない。**名所の一覧にないことと、知識を調べて答えることは、別。**「ご希望なら調べます」型の文も出さない。**必要なら、先に調べる（第1部（段階58）の公式ページの取得、第9部の記録が先の規則と同じ）。
5. **末尾の固定質問**（「好みを1つ教えてください。近さと、見られる種類のどちらを優先しますか」）は、**出さない**（本人の指示 2026-11-07。段階57の第13部で実装済みのはず）。代わりに、**関連して答えられる事実を最大2つ**、事実の形で添えてよい（例: 「豆桜は、箱根の恩賜箱根公園で、3月下旬〜4月中旬に見られます」）。できないことは提案しない。
6. **雑談的な発見**（「〜というのもあるんだ」「へえ」など）: 興味を受けて、**短い知識（2〜4行）と関連1つ**で答える。長い一覧にしない。
7. **検査器に足す**: 知識・違い・比較の答えで、(a) 先頭が名所の列挙になっていないこと、(b) 末尾の固定質問が出ていないこと、(c) 「調べます」型の文が出ていないこと、(d) 事実が知識カード（または記録した事実）と一致していること、(e) 出典が本文の事実に対応していること。
