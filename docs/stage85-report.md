## 第4部 細かい直し

1. **ページの案内がフックに止められた件(11/15)**: 会話の記録で確かめた。原因は、Sonnet が `ask verify … > final.txt; python -m ikimonobiyori.ask page` を **1 回のコマンドで続けて実行**したこと。フックは「ask page が ask verify より後の呼び出し」のときだけ案内の文を受け入れていたので、同じ呼び出しでは順番が分からず、答えの文と比べて止めた(2 回)。さらに Sonnet はそのあと ask verify をやり直していた。直し: 同じ呼び出しの中ではコマンドの中の位置で前後を決める/ページのあとで ask verify をやり直しても、ページの案内の文なら通す/比べ方は空白・改行・行の頭の記号・リンクの書き方(<URL>・[文字](URL))の違いを見ない/ページの呼び出しの形を `ask page;` `ask page 2>&1` にも当てる。記録の形を写した合成のテストで確かめた。第5部 q6 で止められなかった(下)。
2. **観察記録と暦の枠**: 語りの材料に「例年この時期の観察記録」を最大 2 点・「季節の暦」を 1 点、先に取っておく(紅葉だけの質問でも、分類を決めない形で地域の観察記録と暦を引く)。公式の現況がない候補には、その地域の観察記録の印を候補のそばに置く(「・公式の現況がなければ、地域の観察記録 [O001] の傾向を続けて書ける」)。
3. **作業の途中の文**: 手順書への書き足しをやめた。SKILL.md・CLAUDE.md・AGENTS.md の「作業の説明を書かない」(4 か所)を 0 節の 1 か所にまとめ、docs/guide-mode.md の重なりも消した(SKILL.md 14,995 → 14,939 バイト。この段階で足した出典の 1 行を含めても減った)。**途中の文は、内部の言葉(F001 のような印・検査・資料)が入っていなければ不具合として扱わない**と決めた。
4. **`ask knowledge search --place` の取り下げたカード**: 既定では出さない(`--include-retired` で出す。出すときは `retired` の印と理由を付ける)。
