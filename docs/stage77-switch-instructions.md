## 1. 第1部: 直し

### 1. 現況の日付と、対象の日

- 現況の事実の「○月○日時点」が対象の日（今週末など）より前のとき、その状態を**対象の日の状態として言い切る文**を、`ask verify` で不合格にする。
  - だめな例: 「今週末の紅葉は、足尾では真っ盛りです」（根拠は11/7時点）。
  - よい例: 「11月7日時点では真っ盛りでした。今週末は盛りを過ぎているかもしれません」「今週末は見頃に入る見込みです」。
- 通すのは、時点を示した過去・現在の報告と、見込みの言い回し（見込み・可能性・〜ころ・〜かもしれません など）。語の一覧は設定ファイルに持つ。
- guide-voice.md に、この決まりとよい例を足す。**止めすぎないこと**を、段階76の C2 の13本で確かめる（直すべき文だけが止まること）。

### 2. 行事の質問のカード

- 行事（観察会・講座・まつり）を聞く質問では、資料に「一般の話」のカードを入れない。行事の場所・対象に直接結びつくカードだけを入れる。

### 3. 野鳥でも、遠くの候補

- 段階76 第1部の「例年の目安の候補」を、野鳥でも同じように資料に入れる。範囲の指定がない野鳥・渡り鳥の質問では、遠くの地域の候補を合わせて3件まで（例: 記録にあれば、白鳥の飛来地）。
- 確かめること: 「渡り鳥が来ているとききました」の資料に、白鳥など近場以外の候補が入ること。

### 4. 出典と表記

- 出典の行に、名前が空のものを出さない。名前がないときは、サイトのドメイン名を出す。
- **発行元の区分のぶれ**を直す: 同じ発行元が、答えによって「公式」と「公式ではありません」に分かれないこと（段階75・76で、神奈川県観光協会がぶれた）。区分は発行元ごとに1つに決まるようにし、テストを足す。自治体・観光協会・公園管理者・施設運営者が、**自分の管理する場所・行事**について書いたページが「公式」。観光協会が他者の施設を紹介するページの扱いは、今ある決まり（publisher.yaml）に従い、ぶれだけをなくす。判断が要る場合は報告書に書く。
- 日付は西暦にそろえる（「令和8年11月19日」→「2026年11月19日」）。資料を作るときに直し、`ask verify` は和暦と西暦を同じ日付として照らす。

### 5. 今までの形の崩れ

- `ask answer` の「今の状況はの活動で13種(…」の崩れた行を直す（境川遊水地の記録。元の記録の取り込みが原因なら、記録の側を直す）。回帰テストに足す。

## 2. 第2部: 既定の切り替え

1. data\ask\guide_mode.yaml の answer_form を、新しい形にする。
2. **会話での手順**（Claude Code）: 質問を受けたら、`ask brief` → 資料と guide-voice.md だけをもとに下書きを書く → `ask verify` → 合格した最終の文だけを出す。不合格は2回まで書き直し、3回目は `ask answer` の答えを出す（今までどおり、必ず答えが出る）。下書きを書くあいだ、Web 検索やほかのコマンドで事実を足さない。
3. **続けて聞く質問**: 前の質問の資料を引き継ぐ（`--prev`）。
4. **今までの形が受け持つもの**（新しい形にしない）: 単体での実行（`ask answer` を直接使う）、表にして比べる・写真つきのページを作るなどの今ある機能、新しい形が失敗したときの控え。新しい形の答えのあとに「表にできます」などの案内を自動で足さない。
5. **戻し方**: 設定の1行で今までの形に戻せること。戻し方を docs\guide-mode.md の先頭に書く。
6. **手順書**: CLAUDE.md と SKILL.md を、新しい形の手順が先になるよう書き直す。SKILL.md は15,000バイト以内、CLAUDE.md は今の大きさを超えない。骨組み用の細かい決まりは消さず、docs に移して参照にする（今までの形で必要なため）。
7. Stop フックと `ask final-check` が、切り替えたあとの会話で正しく働くこと（合格した最終の文は通る。照合を通していない文は止まる）を、テストで確かめる。
