## 2. 第2部（先に実行）: 台帳の新しい種別「ビジターセンター・自然観察施設」と取り扱い規則

台帳（情報源）に、新しい種別を作る。

1. 項目: 施設名／運営主体（環境省・都道府県・市・日本野鳥の会・自然公園財団など）／施設の公式サイト／「最新の自然情報」のページの URL／更新頻度（毎週・随時など）／形式（HTML・PDF・画像）／更新の季節（通年か、冬は休止か）／規約・ポリシーのページの有無と、**転載・自動取得に関する記載の要約（短く）**／横浜から直線250km前後の範囲か／区分（施設自身の発信＝公式、第三者サイト掲載＝紹介）。
2. **使うもの**: 日付、状態の語（短い語句、30文字以内）、種名（1語ずつ。1施設・1日付につき最大10種）、URL、開館時間・休館日。**文章は保存・転載・要約しない**（山と溪谷オンラインと同じ考え方）。取得した全文は、必要な事実を取り出したら破棄する。
3. **公式サイトの文章でも、記事・お便りの文章は使わない**。答えでは「○○ビジターセンター発信、○/○時点」の形で、短い語と日付と URL を出す。
4. **承認**: 新しく足す施設の情報源は**すべて承認待ち（pending）**で台帳に足す。承認は本人が行う（紅葉の台帳の承認者はユーザーのみという既存の決まり）。台帳の備考に、規約メモ（転載・自動取得に関する記載の有無）を書き、**承認の判断材料**にする。「無断転載を禁ずる」などの明示がある施設は、備考に「転載禁止の明示あり」と書く。
5. **対象外**: Facebook・X・Instagram などのSNS（ログイン・規約の面で使わない）。第三者サイトに掲載された形（山と溪谷オンライン、ウェザーニュース、tenki.jp）。
6. **形式**: HTML のページを優先する。PDF は、新しいライブラリを足さずに本文が読める場合だけ使い、読めなければ「PDF 本文が読めず」と報告書に書く。
7. **季節の終わり**: 更新が止まる施設（例: 八島は10月末で終了）は、「今シーズン最後」の日付を超えたら、今年の情報としては使わない。年つきの日付で判定する（season.py と曜日チェックを使う）。
8. テストを足す（合成データ、通信なし）: 項目の検証、30文字・10種の上限、承認待ちが答えに出ないこと、転載禁止の明示がある施設の扱い、シーズン終了後に使われないこと。

## 7. 第7部（最初に実行）: 曜日チェックの年またぎの修正（別 commit。通信なし）

3. 今シーズンの定義は、これまでどおり 9月1日〜翌年8月31日。年またぎの期間は、開始日が今シーズン内なら今シーズンとして扱う。
4. 合成データでテストを足す（通信なし）: 年をまたぐ期間が落ちない／曜日が合わない日付は落ちる／年が省略された終了日の補完。例（2026年の暦で整合する値）: 2026年12月25日は金曜、2027年1月1日は金曜、2027年1月3日は日曜。
5. 段階54で保留した「Moonlight Rose Garden」（期間が2026〜2027年にまたがる）を、公式ページで年つきの日付を確認できれば、まつり・イベントとして足す。確認できなければ足さず、報告書に「未確認」と書く。

## 8. 第8部（第7部の次に実行）: 山と溪谷オンラインの URL の削除（本人の決定 2026-11-06。別 commit。通信なし）

背景: 花・野草のデータ（wildflower_facts.yaml など）に、山と溪谷オンライン（yamakei-online.com）の URL と、それを出どころとする花期が残っている。本人が「山と溪谷オンラインの URL を消してください」と決めた。

1. **対象**: 花・野草・高山植物・名所のデータ（wildflower_facts.yaml、花のカタログ flowers.yaml、sites.yaml、spots.yaml、花暦など、data 以下と、生成物・キャッシュ・保存データ（IKIMONOBIYORI_DATA_DIR）の事実データ）にある yamakei-online.com の URL をすべて削除する。
2. **その URL だけが出どころの事実**（花期、名所の記載、「雪解け直後」などの記述）は、出どころを失うので**削除**する（推測で残さない）。
3. **他に独立した出どころ**（YAMA HACK、立山黒部アルペンルート、観光庁の解説文など）がある事実は、その出どころだけを残す。
4. 影響する項目（例: コマクサ、ハクサンフウロ、ハクサンコザクラ、平標山、会津駒ヶ岳。実際の対象はデータで確かめる）を、報告書に表で出す（項目、変更前の出どころの数、変更後の出どころの数、削除したか・残したか）。
5. 出どころが1件になって、紹介サイトの食い違い（「紹介サイトで幅がある」の併記）が成り立たなくなった項目は、併記をやめて1件の値だけにする。**定評（独立した出どころが複数）の条件を満たさなくなった項目は、定評のラベルを外し、「参考」に下げる**（既存の仕組みを使う）。
