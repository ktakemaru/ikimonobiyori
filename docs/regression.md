これまでの試用で見つかった答えの崩れを、今後の変更で再発させないための仕組みです。通信せず、約5秒で終わります。CI（`python -X utf8 -m unittest discover -s tests`）にも `tests/test_regress.py` として入っています。

## 実行
```
python -X utf8 -m ikimonobiyori.regress            # 全部（最後の行: N/N 件が期待どおり）
python -X utf8 -m ikimonobiyori.regress --case defect-date-range
python -X utf8 -m ikimonobiyori.regress --json
```
終了コード 0 = すべて期待どおり、1 = 外れがある。

## 何を確かめるか
`ikimonobiyori/data/regress/cases.yaml` に、代表的な質問が20件あります（今週末・来週末、東京・箱根・日光・神奈川、まつり、高山植物、野鳥、範囲外、写真つきページ、既知の崩れ8件）。入力は合成データで、実在のページの文章は使いません。

- `expect: ok` の答え: 検査器（`ask_verify`）と共通の条件を全部通ること。
- `expect_fail: [コード]` の答え: 既知の崩れを再現した答え。検査がそのコードで見つけること（見つけられなければ検査が劣化したということ）。

共通の条件（`regress.common_checks`）: 先頭に結論の文／作業の事情・内部用語・禁止語が出ない／状態の日付が1つ（範囲にしない）／ウェザーニュース・tenki.jp 由来が出ない／日付と曜日が今年の暦と合う／承認待ちの情報源（山と溪谷オンライン掲載）が出ない。検査器側で、冒頭とおすすめの一致、出典と本文の対応、断定的な見込み、作業報告も確かめます。

## 失敗したとき
1. 外れた質問の ID と理由が出ます。まず、直近の変更で出力が変わっていないか確認します。
2. **条件を緩めて合わせない**。原因を調べて、コード側を直します。
3. 質問を足すときは `cases.yaml` に合成の入力と答えを足し、`expect` を決めます。
