## 3. 第2部: 質問の振り分け（A）

1. 振り分けを「**何について**（場所／種・テーマ／地域全体）」×「**日付**（あり／なし）」の組み合わせにする。

   | | 日付なし | 日付あり（今日・今週末・来週末など） |
   |---|---|---|
   | 場所（山・名所・エリア） | 見どころ（段階65） | **見どころ＋その場所の今の状況**（新規） |
   | 種・テーマ（カワセミ・ホタル・紫陽花・ススキなど） | 時期と場所（段階64） | **その種の名所＋その日の見込み・記録**（新規） |
   | 地域全体・指定なし | 時期と場所 | 計画（これまでどおり） |
   | 種・テーマの組み合わせ（「渡り鳥と紅葉」） | 同じ場所・近くの組み合わせ | 同じ場所・近くの組み合わせ＋その日の見込み |

2. **場所＋日付**: 冒頭に山のカード・見どころ（季節はその日の月を先に）、続けて「その日の見込み」（その場所の現況・例年の見頃・行事・施設の発信）、行く前に確認すること。**関東全体の一覧にしない**。陣馬山・大山・高尾山の3問を受け入れ条件にする。
3. **種＋日付**: その種の名所（カタログ・カード）から、その日に時期が合うものを先に、合わないものは「時期の外」と1行で。野鳥は、公園の観察記録・施設の発信に、その種の名があれば日付つきで出す。「今週末、カワセミを見たい」で水元公園などが出ることを受け入れ条件にする。
4. **組み合わせ**: 「AとBが見られる場所」は、段階58 第10部6の仕組み（同じ地点、または約20km以内）を使い、組み合わせを先に出す。見つからないときだけ、別々の一覧にする（「同じ場所や近くでは確認できていません」と1文）。
5. **エリア名の解決**: 「富士山界隈」「富士山周辺」「富士五湖」などを、エリア辞書の同じエリアに解決する（別名辞書に足す）。エリア＋花で0件のときは、そのエリアの花の季節の案内（時期と場所の型）につなぐ。「0件」だけで終わらせない。
6. **複数テーマ**: 「紅葉やススキ、そのほか秋」で候補が1件になった原因を調べて直す（テーマの1つに候補がないとき、全体が絞られていないか）。
7. テストを足す（各組み合わせの合成データ）。

## 4. 第3部: 記録がないときの自動の調べ（B）

1. `ask answer` は、質問の場所・種について**記録がない、または足りない**とき、答えと一緒に「調べる対象」（場所・種・市町村・探す語）を構造化して返す（例: `needs_research: [{"what": "ホタル", "where": "あきる野市"}]`）。利用者向けの答えには出さない。
2. **スキルの手順**: `needs_research` があれば、エージェントは**利用者に聞かずに**、次を行ってから `ask answer` を呼び直す。
   1. 検索で公式サイト（市町村・観光協会・施設・公園の管理者）の URL を探す（検索の要約は行き先を探すためだけに使う。事実にしない）
   2. 本文を読む（1回の質問で最大5ページ）
   3. 読めた事実を記録する（名所の登録、例年の時期、種、行事、知識カード）
   4. `ask answer` を呼び直し、`ask final-check` に通して送る
3. 調べても見つからないときだけ、答えに「（場所）の（種）は、公式の情報では確かめられませんでした」と1文で書く。「お答えできません」「調べることもできます」と書かない。
4. **名所の登録に、今の状態をいらなくする**: 名所カタログへの登録（場所・種・例年の時期・出典）は、今の状態（状態の語）がなくてもできるようにする。今の状態は、読めたときだけ別に記録する。状態が画像で読めないときは、状態を記録しない（推測しない）。
5. 受け入れ: 「あきる野市でホタルが見られるところと時期は?」「箱根にススキの名所はない?」で、利用者に聞かずに調べて記録し、答えが出る。
6. テストを足す（合成データ。通信なしで `needs_research` が出ること、記録後に答えが出ること）。
