## 判断したこと(エージェントの判断)

- **サブエージェント**: マスター指示書は「サブエージェントを使わない」、各指示書は「取得は web-fetch エージェント経由」。この環境に直接の WebFetch がないので、取得だけ `web-fetch` を使い、それ以外には使わなかった。
- **`guide page` の `--theme` の省略時**: 既存テストが省略時に野鳥のページを期待するので、引数の既定は残した。「該当がないとき野鳥にする」分岐はなく、対応外の語は終了コード 2 で止まる。原因の一つだった「花のページも bird-guide.html に上書きする」点は、`flower-guide.html` に分けて直した。
- **`guide page --theme 紅葉`**: エラーのまま。紅葉は直前の答えの計画から作る(`ask page`)ので、対応の一覧に「紅葉(直前の答えから)」と示す。
- **野鳥だけの答えのページ**: 既存どおり公園ごとのページ(`park_page`)。花・紅葉・総合だけ新しいページ(`plan_page`)。
- **`ask refresh --plan` は読むページの一覧を出すだけ**: Python の実通信は規則6 で制限されるので、取得はエージェントの道具で行う。第10部の `--spot` の代わりに `ask place` が検索語を返す。
- **見込みの区分の順位**: 第12部の「区分の優先は維持」と「高尾山(現況なし)が昭和記念公園(現況あり)より下」は、実データでは両立しなかった(高尾山 in_peak、昭和記念公園 toward)。現況なしの候補は並びの区分を「見頃に向かう」までに抑える値(`evidence.typical_only_rank_cap`。暫定)を足して両立させた。
- **文字数の上限**: 節が複数の答えは 1,500 字 × 節の数(暫定)。
- **骨組み `skeleton.py`**: 動作確認に必要なので第7部で先に入れた(段階58 第9部で仕上げる)。
- **自分の誤りの訂正**: 動作確認の記録で、日光の社寺の現況を誤った名所 ID(中禅寺湖)で 1 行書いた。データ置き場のその 1 行だけを取り除き、正しく記録し直した(今回自分が作った変更の取り消し)。
