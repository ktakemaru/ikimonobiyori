## 2. 守ること（既存の決定を変えない）

## 3. 台帳を「公式」と「紹介・予報」に分ける
### 3-1. 背景
tests/test_sources.py の test_the_repository_registry_keeps_the_rules は、台帳に気象会社などの発行元を置くことを禁じている。このため段階45では、日本気象・tenki.jp・ウェザーニュースを台帳に入れられなかった。
ウォーカープラスは、禁止リストの語に当たらないため入れた。

### 3-2. やること
- 既存のテストの禁止リストは**変えない**（緩めない）。
- 紹介サイト・予報会社用の台帳を、公式の台帳とは別のファイルとして新設する（設計はこのリポジトリの構成に合わせて最小にする）。
- 新設する台帳の対象: 日本気象（見頃予想）、tenki.jp、ウォーカープラス（段階45で公式の台帳に入れたものを、整合のためこちらへ移す。移すと影響が大きい場合は、移さずに理由を報告書に書く）。
- 新設した台帳にも、読める条件・通信先の承認・確度ラベル（「紹介サイト（公式ではない）」「予報会社」）を持たせる。
- 新設した台帳用のテストを書く。公式の台帳のテストはそのまま通ること。
- 答えを組み立てるコードが、新しい台帳を読んで候補に使うようにする。公式の台帳の優先順位は変えず、紹介・予報側は「公式ではありません」を添える。
- 変更の影響範囲を、報告書に表で書く。

## 4. tenki.jp の現況の取り込み、ウェザーニュースの確認
### 4-1. tenki.jp（https://tenki.jp/kouyou/）
- 取得できるか、robots.txt と利用規約で自動取得が禁じられていないかを先に確認する。禁じられていれば、読まずに「人が開くリンク」として記録して止める。
- 読める場合：地点ごとの色づき段階と日付が出ているかを、実物で確かめる。
  - 日付つきで読めたら、status_log に記録し、候補に使う。確度ラベルは「紹介サイト（公式ではない）」。
  - 読めない（本文が少ない・段階や日付がない）なら、その事実を記録し、検索の要約に頼る代わりの読み方を最大2通り試す。それでも読めなければ、読めないと記録して止める。
- ページの構造が安定していて決まった形で読めるなら、日光・箱根と同様にコードで読む案を報告書に提案する（実装は、テストが書ける場合のみ）。

### 4-2. ウェザーニュース（https://weathernews.jp/koyo/）
段階45では「読まない」とした。段階45の確認で、robots.txt に禁止の記載が見当たらなかった。次の順で決める。
1. robots.txt を実際に読み、/koyo 以下が禁止されているか確認する。
2. 利用規約で、自動取得・スクレイピング・転載が禁じられていないか確認する。
3. どちらも禁止の記載がなければ、読み方の確認（地点ごとの色づき段階と日付）まで行い、tenki.jp と同じ扱いにする。
4. どちらか一方でも禁止または判断に迷う記載があれば、読まず、「人が開くリンク」のままにして、その理由（見た文言の出どころ）を報告書に書く。判断に迷う場合は読まない側に倒す。
