# イキモノビヨリ（紅葉）検証計画 — 設計のみ（実装しない）

目的: `validated: false`（`go` を出せない）の紅葉プロファイルを、今季の実際の紅葉と突き合わせて、**どの目安・どの段階の定義が使えるか**を判断する材料を集める。
合格基準の数値は**空欄**で、私（ユーザー）と決める。この文書は実装ではなく、何を記録し、何と比べ、どう判定するかの設計。

## 1. 何を記録するか（予測側。毎日のスナップショットから機械的に）
地点（`site_id`）× 予測の対象日 × 予測を作った日（リード日数）ごとに1行:

| 項目 | 内容 |
|---|---|
| `site_id` / 地点名 / 標高（カタログ） | 地点の識別 |
| **参考にした外部情報のスポット名と、そのスポットの標高** | 外部の見頃情報（例: 谷川岳ヨッホ）はモデルの地点（山頂・グリッド）と標高が違いうる。比べる相手の標高を必ず記録し、標高差ごとのずれを見る（2026-10-14 の谷川岳の参考照合では、スポットの標高が未確認だった） |
| 応答の `elevation`（グリッドの標高） | 山頂との差（気温がグリッド標高のものであるため） |
| 予測を作った日時（`generated_at`）、対象日、リード日数 | 予測の鮮度 |
| 入力: 日最低気温の系列（直近の平均に使った `mean_window_days` 日分）、平均 M | `evidence`（`min_temp_mean_window` など） |
| 予測した `phenology_stage` と `band`、点数 | 提案そのもの |
| 使った閾値（`start_min_temp_c`・`advance_min_temp_c`・`strong_min_temp_c`・`mean_window_days`）とプロファイルの版 | 閾値を後で変えても、記録と照合できるように |

保存先（案）: `snapshots/ikimonobiyori/` の提案 JSON をそのまま日付つきで残し、別に集計用の表（CSV など）を作る（実装は別途）。

## 2. 何と突き合わせるか（正解側。候補。いずれも**検証用の参考データ**で、気温の目安の出典とは別）
| 候補 | 内容 | 長所 / 限界 |
|---|---|---|
| 気象庁 生物季節観測（かえで: 紅葉日） | 気象官署の標本木（いろはかえで）の目視。「葉の色の大部分が紅色に変わり、緑色がほとんど認められなくなった最初の日」（指針 2.1.2、3.4） | 定義が公式。ただし官署の標本木は平地で、山の地点とは標高も種も違う。観測は「見頃」ではなく「大部分が紅葉した日」 |
| 観光協会・気象会社の見頃情報 | tenki.jp、ウェザーニュースなどの「色づき始め／見頃／落葉」の現況（スポット単位） | 地点に近い。ただし形式・更新頻度がまちまちで、判定基準が非公開。スクレイピングの可否・利用条件は未確認 |
| 利用者の目視記録 | 実際に行った人の報告（写真・コメント） | 最も実態に近いが、件数が少なく、記録の形式が揃わない |
| iNaturalist の紅葉・落葉の記録 | 観察記録に紅葉の注釈があれば | 注釈の有無・件数は**未確認** |

突き合わせの単位: 地点 × 日。外部情報の段階（色づき前／色づき始め／見頃／終盤）を、プロファイルの段階（`before_bud` / `early_bloom` / `peak` / `late`）に対応づける表を、記録の開始前に決める（対応づけの規則は私と決める）。

## 3. どう判定するか（設計）
1. **一致度**: 外部情報の段階とモデルの段階が一致した割合（段階ごと、地点ごと、標高帯ごと）。1段階ずれ・2段階以上のずれも別に数える。
2. **方向のずれ**: モデルが進みすぎ／遅れすぎの傾向（ずれの符号）。気温がグリッド標高のものであることによる標高の偏りも見る。
3. **日付のずれ**: 外部情報の「見頃入り」の日と、モデルが最初に `peak` を出した日の差（日数）。
4. **閾値の感度**: `start_min_temp_c`（8）・`advance_min_temp_c`（6）・`mean_window_days`（7）を動かしたときの一致度（どの値が実測と合うか）。**閾値の変更は検証結果を見て私と決める**（自動では変えない）。
5. **カバレッジ**: 期間外（`out_of_season`）で返らなかった日に、実際は色づいていた例がないか（`season.months` が狭すぎないか）。
6. **上限の解除**: `validated: true` にして `go` を許す条件は、下の合格基準を満たし、私が承認したときだけ。
