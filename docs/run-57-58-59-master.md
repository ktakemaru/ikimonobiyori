## 1. ブランチの積み方（push ができないため、積んで進める）

- push・PR・マージは、権限で拒否される。回避しない。**マージを待たずに、ブランチを積んで進める。**
- 段階57: `main` から `stage57` を切る（すでにあれば、それを使う）。
- 段階58: 段階57の最後の commit の上に `stage58` を切る（`git checkout stage57` → `git checkout -b stage58`）。
- 段階59: 段階58の最後の commit の上に `stage59` を切る。
- 各指示書の「前の段階が未マージなら、前の段階のブランチから切り、報告書の先頭に書く」規則を、この積み方で適用する。
- **「前の段階が実行中（progress が未完了）なら、何もせず報告して終了する」規則は、この連続実行では適用しない。**前の段階について、すべての部が「完了」「未完了（理由が報告書にある）」「スキップ（理由つき）」のいずれかになっていれば、前の段階は**終了**とみなして、次へ進む。
- 前の段階で未完了の部があり、次の段階がそれに依存する場合は、依存する項目だけをスキップし、報告書の「判断したこと」に書いて、残りを実行する。

## 2. 実行の手順（各段階で同じ）

1. 現在のブランチ・`git status`・`docs\run-master-progress.md` を確認する（ブランチを間違えたら、作業を始めず、進捗ファイルに従って切り替える。未コミットの変更があれば、その段階の作業中のものか確認して、続ける）。
2. その段階の指示書を読み（部ごとに必要な範囲を読んでよい）、**その指示書の「実行順」**に従って、各部を実行する。各部は、別 commit。
   - 段階57の実行順: 第1部 → … → 第6部 → 第8部 → 第9部 → 第10部 → 第11部 → 第12部 → 第13部 → 第7部。
   - 段階58の実行順: 第1部 → … → 第7部 → 第9部 → 第10部 → 第8部。
   - 段階59の実行順: 第6部 → 第1部 → … → 第5部 → 第7部。
3. **各部の commit の条件**: 全テストを、**4つ程度の部分に分けて、別のプロセスで順に実行**し（メモリ不足を避けるため）、合計の件数が、数えた全体の件数と一致して、すべて OK であること。落ちたら、原因を調べて直す（同じ部で最大3回）。直らなければ、その部だけ戻して、次の部へ進む（テストの期待値や条件を緩めたり、削除したりしない。許可された更新は、各指示書に書かれたものだけ）。
4. 各部が終わるたびに、その段階の progress ファイルと、`docs\run-master-progress.md` に追記する（段階、部、状態、最後の commit の短い ID、次にやること）。
5. 段階の最後の部が終わったら、**全テストを4分割で1回**実行し、その段階の報告書（docs\stageNN-report.md）を、各指示書の指定どおりに書き、commit する。
6. 次の段階へ進む（1. の積み方）。

## 3. 使用量・時間・メモリの管理

- **サブエージェントは使わない**（使用量の節約）。
- 画面への出力は、最小限にする。テストの出力は、最後の数行と件数だけを見る（`cut -c1-200`、`tail` などで絞る）。大きなファイルは、必要な範囲だけ読む。`git diff` は `--stat` を使う。
- **コンテキストが圧縮されたとき**（または、不安になったとき）は、最初に、`docs\run-master-progress.md` と、今の段階の progress ファイルを読み直し、その状態から続ける。指示書は、必要な部だけ読み直す。
- 1つの部が、1時間以上進まないとき（同じ失敗の繰り返し、通信の待ち）は、その部を「未完了（理由）」として記録し、次へ進む。
- 通信を伴う部は、各指示書の取得の上限と間隔（同じホストへ1秒以上、失敗が10回連続したら中断）を守る。
- 使用上限に達して止まる場合がある。その場合は、止まる前に、進捗ファイルが最新になっていること（各部のあとの追記）を、確かめておく。**再開は、本人が、同じ依頼を貼って行う。**

## 4. 禁止事項

- push・PR・マージ（拒否されたら回避しない）。
- **承認（approval）の記入**。今回の指示書には、承認の記入は含まれない。本人が指示文で明示したものだけを記入する規則であり、この連続実行では、行わない。
- 破壊的操作（削除、`git reset --hard`、`--force`、`git clean`）は、今回の連続実行で自分が作った変更の取り消し以外では、行わない。
- 他のブランチの履歴の書き換え、main への直接の commit。
- 質問すること（無人実行のため。迷ったら、各指示書の「迷ったら」の順で決め、報告書に書く）。

## 5. 中断条件（連鎖を止める）

- ある段階の最後の全テスト（4分割）が、3回直しても通らないとき: **その段階で止め**、次の段階に進まない（壊れたコードの上に積まない）。原因と、最後に通った commit の ID を、`docs\run-master-report.md` に書いて終了する。
- 作業ツリーの状態が、想定外のとき（他のウィンドウの変更が混ざっている、ブランチが違うなど）: 作業を始めず、状態を `docs\run-master-report.md` に書いて終了する。
