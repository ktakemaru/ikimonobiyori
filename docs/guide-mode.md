# ガイドの形(段階75〜77): ガイドが書き、コードが裏を取る

> **最後に送るのは `ask verify` の出した文だけ。前にも後ろにも何も足さない。作業の説明・英語のメモを書かない。**(段階78)
>
> **戻し方**: `ikimonobiyori/data/ask/guide_mode.yaml` の 1 行 `answer_form: guide` を `answer_form: classic` にすると、今までの形(`ask answer` の出力をそのまま送る)に戻る。Stop フックの案内も今までの形のものになる。

**段階77 から既定はこの形**(`answer_form: guide`)。今までの形(`ask answer`)は、単体の実行・表にして比べる・写真つきのページ・この形が 3 回不合格のときの控えとして残る。この形の答えのあとに「表にできます」などの案内を足さない。`ask answer` を直接実行したときは、答えは今までどおりで、標準エラーにこの手順への 1 行が足される。

| 役割 | 誰が |
|---|---|
| 答えを書く(なぜ今見られるのか・どこをどう見るか・つながり) | AI(書き方は docs/guide-voice.md) |
| 腐りやすい事実を記録と照らす(今年の現況・日付・行事の期間・開園時間・料金・電話・通行止め・範囲外の地名) | コード(`ask verify --brief`) |
| AI に渡す資料(候補と順位・確かめた事実・知識カード・足りないもの・決まり) | コード(`ask brief`) |

## 1. 手順

1. **資料を作る**: `python -X utf8 -m ikimonobiyori.ask brief "<質問の文>"`(段階76: 候補は「今年の現況あり」と「例年の目安」(ガイドのカタログから。範囲が広い質問は地域の組ごとに最大 2 件、ほかは遠くの地域から 3 件まで)。カードは場所・種・テーマ・季節から最大 8 枚で、結びつき(この場所の話・この種の話・一般の話)つき。候補・質問の場所に結びつく冬季閉鎖は「確かめた事実」の安全・規制)
   - 標準出力は 3 行: 資料の id・JSON のパス・人が読む Markdown のパス(データ置き場の `briefs/`)。
   - 続けて聞く質問は `--prev <前の資料の id>`(前の事実とカードを引き継ぐ)。`--now` で時刻を決められる(同じ質問・同じ now・同じ記録なら同じ資料)。
   - 通信しない。材料は今の `ask answer` と同じ(記録・名所カタログ・知識カード・台帳)。承認待ちの情報源・使わない情報源の事実は入らない。
2. **書く**: 資料の Markdown と docs/guide-voice.md だけを見て、下書きを書く(段階76: 書き手には資料と手本を読むことと下書きを書くことだけをさせる。コマンドの実行・Web 検索をさせない)。腐りやすい事実を含む文の終わりに `[F012]`・`[K034]`、最後に `[場所]` の一覧。
3. **裏を取る**: `python -X utf8 -m ikimonobiyori.ask verify <下書きのファイル> --brief <id>`
   - 終了コード 0: 標準出力が**送る文**(印と場所の一覧を取り除き、確かめた出典を日付と公式かどうかつきで並べた最終の文)。
   - 終了コード 1: 不合格。標準エラーに、文ごとの理由と直し方。直して同じコマンドをもう一度。
   - **書き直しは 2 回まで**。3 回目も不合格なら、今の `ask answer` の答えが標準出力に出る(終了コード 0。必ず答えが出る)。
4. **送る**: `ask verify` の標準出力を一字一句そのまま送る。**前にも後ろにも何も足さない**(段階78: 「資料から下書きを書き、検査に合格しました。合格した答えを、そのまま送ります。」のような前置き・作業の説明・英語のメモは Stop フックに止められ、答えが 2 回見える。道具を呼ぶあいだの文(「Same sentence needed; …」など)も書かない)。

## 2. 照らす内容(要点)

- 印のある文: 印の id が資料にあり、文の日付・月・旬・時刻・料金・電話・URL・(今の)状態の語が、その事実の値と合う。今の状態の文の根拠は「今年の現況」の事実(行事・例年の目安では通らない)。行事と期間・通行止めは、行事・施設・安全の事実が根拠。
- 印のない文: 日付(今日・今週末・来週末・質問の対象の日を除く)・時刻・金額・電話・URL、今の語と状態の語、行事の語と期間、通行止め・閉鎖・規制、記録にある場所の名前と状態の語・月の表現、があれば不合格。場所の名前を含まない季節の一般的な説明は合格。
- 場所: 「記録」は辞書(名所カタログ・エリア・山・未確認の名所・資料の候補)にあること。「知識」は 3 か所まで・範囲の都県・「確かめていない」と分かる書き方。合格すると「知識」の場所は未確認の名所として記録される(あとで公式ページで確かめる材料)。
- 今までの検査の部品: 使わない情報源・内部の言葉・作業の事情・最後の質問・長い引用・範囲の外の都県・聞かれた場所のすり替え。
- 骨組み用の言い回しの検査は当てない。最後の質問の検査は、読む人への問いかけ(「〜しますか」「〜でしょうか」「?」)だけを止める(段階76。「どちらも…ご確認ください」のような案内は止めない。今までの形の検査は変えない)。
- 公式でない出典の長い断り(「紹介サイトの記載で、公式ではありません」)を文中に書くと止める(段階76。「紹介サイトによると」と短く)。
- 最後の出典には、印を付けた事実のうち URL のあるものだけを並べる(段階76)。
- 記録: データ置き場の `logs/answers.jsonl` に `kind: guide`(資料の id・照らした文の数・書き直しの回数・落ちた検査)。

## 3. Claude Code(フックで強制)

- Stop フック(`.claude/hooks/stop_check.py` → `ikimonobiyori/stop_hook.py`)は、この回に `ask brief` を使ったとき:
  - `ask verify ... --brief` を通していなければ止める(理由: 下書きを通してから送る)。
  - 最終メッセージが `ask verify` の出した文(合格した最終の文か、3 回目の不合格で出た答え)と一致しなければ止める。
  - 一致すれば通す(`ask final-check` を通さなくてよい。通しても、その文はそのまま返る)。
- `ask final-check` も、`ask verify` が出した最終の文と一致するメッセージは、そのまま受け入れる。
- 段階77(既定がこの形): 生き物・お出かけの質問に道具を使わずに答えようとしたときは、この形の手順(`ask brief` → 書く → `ask verify`)を案内して止める。`ask answer` を使った回は、今までどおり `ask final-check` を求める。

## 4. フックのない環境(Codex・ほかのエージェント。段階78 で更新)

フックがないので、次を**必ず**守る(手順として):

1. `ask brief` → 資料を読む。資料に「調べる(資料が薄い)」の節があり、Web が使えるときだけ、その節の手順で公式ページを読んで記録し(§5)、資料を作り直す。Web が使えないときは飛ばす。
2. 下書きを書く。組み立ては docs/guide-voice.md の §1 の順番(①質問への答え ②なぜ今 ③場所ごとに確かめた事実とどこをどう見るか ④注意)。資料の「語りの材料」から少なくとも 1 点を使い、印 [K…] を付ける。書くあいだ、Web 検索やほかのコマンドで事実を足さない。続けて聞く質問は `--prev <前の資料の id>`。
3. 送る前に必ず `ask verify <下書き> --brief <id>` を通す。終了コード 1 なら直して通し直す(2 回まで)。
4. 送るのは `ask verify` の標準出力だけ(一字一句そのまま)。**前にも後ろにも何も足さない**(前置き・作業の説明・英語のメモを書かない)。
5. `ask verify` を通さずに送らない。迷ったら今の形(`ask answer` の出力)を送る。

照合が止めるもの(段階78 で足した): 語りの材料が 2 点以上あるのに 1 点も使っていない(行事・名前だけの質問は除く)/先頭・末尾の作業の説明・英語の文/東京湾の向こう側の距離の数字・「直線」のない距離。

## 5. その場で調べる(段階78 第4部)

- いつ: `ask brief` が、聞かれた種の名所が 0〜1 件・聞かれた場所に名所もカードも事実もない・利用者が挙げた場所の記録がない、と判断したとき。資料の「足りないもの」に「調べる: …」、節「調べる(資料が薄い)」に手順が出る。
- 手順: ① 公式ページの URL を Web 検索で探す(検索の要約を事実にしない) ② `python -X utf8 -m ikimonobiyori.ask research fetch <URL> --brief <id>`(本文が標準出力に出る) ③ 本文で確かめた事実だけを JSON にして `ask research record --brief <id> --file <JSON>` ④ `ask brief` を作り直して、いつもの手順。
- 読んでよいページ: 発行元の区分が「公式」のもの(自治体・観光協会・公園管理者・施設運営者(指定管理者を含む)・国や県の機関)。紹介サイト・使わない情報源は読まない(コードが止める)。観光協会などの独自のドメインで「公式の発行元のページではない」と止まったときは、`--publisher <発行元の名前>` を付ける(名前が公式の形で、ページの運営者の欄(フッター・著作権表示・運営者情報・meta の author/copyright)にその名前があるときだけ読める。本文にあるだけでは読まない。運営者の欄のないページも読まない。段階80・本人の判断 2026-11-11)。同じサイトへの転送(www の有無など)は 1 回だけ追う。
- 上限: 1 つの質問で 3 ページ・最初の取得から 2 分まで(超えたら、そこまでの記録で答える。上限の文には、その資料の番号で最初に取得した時刻が出る。段階80)。robots.txt を先に読み、拒否なら読まない。同じホストへ 1 秒以上。同じ URL は 7 日のあいだ控え(データ置き場の `research/pages/`)を使う。実行ごとの記録は `netlog/requests.jsonl`。
- 記録してよい項目: 名所の名前・都県と市町村・見られる種(kind)・例年の時期(typical)・行く前の注意(notice)・出典(url・publisher)。**今年の現況は記録しない**(情報源の承認が要る)。**行事の期間(まつりの開催日など)を例年の時期にしない**(本文に「例年の見頃」などの記載があるときだけ。コードが止める)。**範囲の後ろの月を省かない**(「4月上旬〜下旬」は前半しか読まれないので「4月上旬〜4月下旬」。コードが止める)。**例年の時期のない記録(notice だけ)は記録できない**(notice は添えるだけ。「行く前に」だけを残すときは `ask record` に `notice`・`source_class: official`・`basis: page` で記録する。段階80)。座標は記録しない(市町村まで)。記録には「その場で調べた」印 `research: {at, brief, question}` が付く(`--publisher` で独自ドメインを読んだ記録は、印に `declared_publisher` も付く)。**その場で調べた記録は、本人の見直しの前から次の答えに使う。印は付けたまま**(本人の判断 2026-11-11)。
- JSON の 1 件の例: `{"subject": "flowers", "name": "○○公園", "prefecture": "静岡県", "city": "○○町", "kind": "菜の花", "typical": "例年1月中旬〜2月下旬", "url": "<読んだ URL>", "publisher": "○○町観光協会", "current_status_page": false}`(`current_status_page: true` は、そのページが今年の現況を出しているとき。承認待ちの情報源の候補として `research/pending_sources.jsonl` に残る。答えには使わない)。
- 見直し: `ask research list`(調べた記録と、承認待ちの情報源の候補の一覧。各記録の `via` に「独自ドメイン(本文の発行元の名前で確かめた)」か「公式の一覧のホスト」が出る)。発行元の名前は、段階80 から運営者の欄で確かめる(本人の指示 2026-11-11)。
- 市区町村の名前の質問(段階80・本人の判断 2026-11-11): 名所の記録(名所カタログ・ガイドのカタログと検索で集めた名所・観察の名所)にある市区町村の名前(「南伊豆」「松田町」。末尾の 市・町・村・区 は省いてよい)が質問にあれば、その市区町村の名所を候補にし、ほかの場所の候補(既定の出発地の近くの名所など)とその事実・ほかの場所の話のカードは資料に入れない。検索で集めた名所は「仮(検索で集めたもの)」と出る。エリア・地域・出発地の辞書で分かる地名(箱根・横浜・秩父など)は今までどおり。
- 仮の名所だけの市区町村(段階80 の追記2・本人の判断 2026-11-11): 市区町村(地域)の候補が検索で集めた仮の名所だけなら、節「調べる」に「「…」の名所が仮(検索で集めたもの)だけ」と出る。公式ページで確かめて `ask research record` すると、その名所(名前が記号を除いて一致するか、片方がもう片方を含むもの)は仮でなくなり、出典は確かめた公式ページになる。確かめられなかった名所は仮のまま。
- 広い地域の名前(段階80 の追記2・本人の判断 2026-11-11): エリア辞書(`data/ask/areas.yaml`)に「伊豆」(伊豆半島)を足した。「伊豆市」と書かれたときだけ伊豆市。長い市区町村の名前の一部(「南伊豆」「伊豆の国」「那須塩原」。辞書の `not_within` も)と、前に漢字・カタカナが続く語の一部は、エリアとして数えない。エリアや市区町村の名前を挙げた質問(「秩父で見られる花は?」「日光の紅葉は?」「伊豆で見られる花」「〜のエリア」)では、候補をその場所の名所だけにする(市区町村が一致するか、名所の辞書の座標がエリアの半径の内。段階80 の追記3・本人の判断 2026-11-11)。その場所の名所が 0 件なら、ほかの場所の候補に置き換えず、「足りないもの」と節「調べる」に出す。出発地として挙げた名前(「秩父から」「大宮から行きやすい場所」)は今までどおり。「富士」だけのときは富士山の周り(富士五湖と静岡側)、「富士市」と書かれたときだけ富士市。秩父(秩父地方の 5 市町)・那須(那須町・那須塩原市)・伊豆(伊豆半島の 15 市町)・富士は、半径ではなく市町で決める(辞書の `membership: cities`。市区町村の欄のない名所だけ座標で。段階80 の追記4)。「那須塩原」は那須塩原市だけ。読んだ事実の記録(紅葉も)にだけある市区町村(那須塩原市)も、市区町村の名前で引ける。対象(紅葉・花・野鳥)や種の名前を聞かれたときは、それに合う名所だけ。
- 同じ場所の候補(段階80 の追記5・本人の判断 2026-11-12): 名前の形が違う同じ場所(「宝登山ロウバイ園」と「長瀞宝登山臘梅園」)は、資料の候補で 1 つにまとめる。同じ市区町村・同じ種で、両方に座標があれば 200m 以内(`guide_mode.yaml` の `merge_same.max_m`)、なければ名前の主な部分(括弧の中・都県と市区町村の名前・種の別名の違いを除いたもの)が同じとき。表に出す名前は公式の出典の事実を持つ候補の名前で、元の名前は `merged_from`、事実は両方を残す。例年の時期の月が重ならないときはまとめない(資料の `candidate_merge_conflicts`)。記録そのものは変えない。
- 辞書にない地名(段階80): どの辞書でも解決できない市区町村の名前(名所の記録もない町)が質問にあるときは、既定の出発地の近くの候補に置き換えない。資料の候補は空、「足りないもの」に「場所の辞書にない地名「…」」、節「調べる」にその地名が出る。
- 答えの字数は照合で止めない(注意だけ。本人の判断 2026-11-11)。
- 足りなかったことの記録(第5部): `ask verify` に合格した答えの「確かめられていません」などの文と、資料の「足りないもの」が `logs/gaps.jsonl` に貯まる。`ask gaps` で対象×場所ごとの回数。次のデータ集めはこの一覧から。
