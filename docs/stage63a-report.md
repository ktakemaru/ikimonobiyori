## 各部

1. **答えが必ず出る**: `ikimonobiyori/answer_run.py`。
   - 経路は次のとおりです。
     - 計画: 紅葉・花・野鳥。地域・エリア・出発地・日付・期間・「近場」などの語を質問から決める。
     - 知識・平年・行事・野草・ガイド型(桜・ホタル)。
   - フォールバックは 1 整えた文章 → 2 骨組み → 3 部分回答 → 4 最低限の答え。最低限の答えは、確認できた範囲・確認できなかったこと・確認の方法で、事実は facts の値だけです。
   - 時間の上限は 180 秒(`plan.yaml` の `answer_run.budget_s`)。整えなおしは 1 回まで(段 1 で使えなければ骨組み)。
   - 質問ごとに別の作業フォルダ。途中で例外が出ても、答えは空にしません。
2. **必須の検査を4つ**: `answer_gates.py` と `answer_contract.json`。
   - 自動修正: 内部用語・作業の事情・質問・一覧にない提案の文を消す、出典を作り直す、字数を超えたら候補を減らす。
   - そのほかの品質・表現は警告です。分類のない新しい ID は、事実の検査として扱います(緩めない)。
3. **局所化**: 誤りを候補ごと・行ごとに分けます(`localize`)。
   - 候補の誤りは、その候補を計画から外します。候補に結びつかない文は、その行だけ外します。安全の検査なら BLOCKED、それ以外は DEGRADED です。
   - 「観察の記録がある」と「今見られる」を、別の主張にしました(`now_visible_unsupported`。安全の検査の中)。
4. **整えた文章の照合**: 骨組みの行ごとの事実の一覧(`skeleton_facts.json`)を作り、整えた文章を照合します。事実の行は一字一句・同じ順で残すことにし、整えてよいのは冒頭の決まり文と「ガイドの目」だけです(段階63 第5部を統合)。従来の `ask polish-check` はデバッグ用にそのまま残しました。
5. **ログ**: 答えごとに 1 行の JSON(データ置き場の `logs/answers.jsonl`)。`ask checks report` で集計します。
6. **仕様を1か所に**: `answer_contract.json` に、答えの形・4つの検査・自動修正・警告・字数・フォールバックの順・検査の ID の説明(100 件)をまとめました。骨組みを作る側と検査器の両方が読みます。`docs/answer-checks.md` はここから作り、テストで一致を確かめます。
7. **テスト**: 下の表。
8. **スキル**: 手順は `ask answer` を 1 回、出力をそのまま答えにします(63b 第4部と同じ commit の流れ)。聞き返さない・断りの 1 行を出さない・読み直しは 1 回だけ。説明文は、お出かけ・生き物の語で起動するようにしました。
9. **段階63 の残り**: 下の「段階63 の積み残し」。
