## 第3部: 資料の先頭に「聞かれた山の名所」の節

### JSON の `asked_mountain`

- 資料のいちばん上の項目で、いつも出します(入らないときは `null`)。`candidates` の直前に置きました。
- 形は `{site_ref, name, candidates: [{name, outlook, facts}]}` です。新しい値は作らず、候補と事実に今ある値を写すだけです。

| 項目 | 中身 |
|---|---|
| `site_ref` | 質問に挙げた山の `yamabiyori:mNNN` |
| `name` | `data/sites.yaml` の名前のまま(例「筑波山(女体山)」) |
| `candidates[].name` | 候補の `name` |
| `candidates[].outlook` | 候補の `outlook`(霧ヶ峰の花のように見込みが無ければ `null`) |
| `candidates[].facts` | その候補の事実の `id`(事実の `place` が候補の名前のもの) |

**入れる条件**(`guide_brief.asked_mountain`):

1. 設定 `mountain_named_candidates.enabled` が `true` であること。
2. 資料に、山の名前から足した候補(`added_by: mountain_name`)が 1 件以上あること。
3. 質問に挙げた山(`_asked_mountains`)のうち、足した候補がその山の名所の組(`_mountain_groups`)に当たる最初の山を入れる。
4. その山の名所でもとから候補にあるものは、足した候補があるときだけ一緒に並べる。今回の 35 問には当たる件がありません。

**入れない資料**: 山の名前の入らない質問、足した候補の無い質問は `null` です。高尾山の 4 問も `null` です(下の理由)。

**高尾山を入れなかった理由**:

- 指示書は「足した候補が無くても、聞かれた山の名所が候補にあれば入れる」としています。
- しかし前回のテスト `test_mountain_named_candidates.py` の `test_not_added` は、「今週末、高尾山で紅葉を見たい」の資料が、設定を入れたときと切ったときで(`generator` を除いて)同じであることを確かめます。
- 一方で指示書は、切ったときに今回足すものも全部切れることを求めています。だから高尾山に入れると、このテストの期待値を変えることになります。
- 「やらない側」を選びました(決めてほしいこと 2)。
