## できたもの(使い方)
- `python -X utf8 -m ikimonobiyori.sources check` 台帳の検査(承認の条件・名所カタログとの一致)
- `... sources weekend --now <ISO>` 候補と読む情報源の一覧(同じページは 1 回)
- `... sources normalize --source <id> --state <記号・語>` 公式の書き方 → 共通の段階(まだ・色づき始め・見ごろ・真っ盛り・色褪せ/落葉)
- `... sources record --read-at <ISO> --batch <json>` 読んだ事実を `IKIMONOBIYORI_DATA_DIR/status_log/autumn_leaves.jsonl` に追記(事実の項目だけ・承認済みだけ・重複なし)
- `... sources v0 --proposal <出力>` v0 の結果を「推定(未検証・段階14で不合格)」として取り出す
- 値(段階・3/7 日・前後 7 日・3〜5 件・記録の項目)は `data/sources/policy.yaml`。コードに数値を持たない。

## 次の段階への提案
1. **野鳥への同じ型の適用**: 探鳥地の公式発信(都県の野鳥公園・ビジターセンターの「最近見られた鳥」など)の台帳を作り、iNaturalist(市民の観察記録)は補助にする。位置の粗さ(area_10km)と配慮は今のまま。
2. **潮汐**: 干潟の探鳥・磯の生き物には潮位が要る。気象庁の潮位表(公共データ利用規約)を一度だけ取り込む案を、利用条件の確認から。
3. **カタログへの名所の追加**: 竜頭滝・霧降高原 キスゲ平・日塩もみじライン・瀬戸合峡など(`docs/stage15-review.md`)。現況の情報源(日光市観光協会)がすでにあるので、追加すればすぐ答えに入る。箱根の地点(仙石原・湖尻など)も同様。
4. **自治体オープンデータの活用**: 自治体標準オープンデータセットの「観光施設一覧」「イベント一覧」(CSV)で、名所の所在地・まつりの日程を補う。利用条件(多くは CC BY)を確認してから。
5. **ハブへの取り込み**: 記録(`status_log`)を、ハブの窓口が「現況」として読める部品にする案。契約 `biyori-proposal/1` は変えずに、`evidence` に公式の状態・更新日・URL を入れられるかを先に確かめる(変えるなら提案)。
6. **ビヨリコンシェルとのつなぎ方**: コンシェルが「今週末どこへ?」と聞かれたら、このスキルの答え(公式の状態・更新日・出典)をそのまま語りの材料にし、ヤマビヨリ(天気)・ホシビヨリ(夜)と組み合わせる。
7. 読めなかった 3 件と状態が画像の 1 件は、ユーザーがブラウザで開いて、台帳の扱いを決める。
