## 第2部 取得のキャッシュ（ページ単位）

1. **取得のキャッシュ**をデータ置き場に作る（例: `cache/pages.jsonl`。リポジトリの外）。1件は、URL・最後に読んだ時刻・読めたか・本文のハッシュ・取り出した事実の記録への参照。**本文は保存しない**（山と溪谷オンライン・転載禁止の施設の決まりを守る。ハッシュと事実だけ）。
2. **読み直しの判定を、「ページの日付」から「最後に読んだ時刻」に変える**。`refresh_targets` は、次の両方に当たるページだけを返す。
   - 最後に読んでから、情報源の種類ごとの有効期間（下の表）を過ぎている
   - かつ、今回の答えの「今回のおすすめ」の候補に関係する
3. 有効期間は設定ファイル（plan.yaml など既存の場所）に置く。初期値：

   | 情報源の種類 | 有効期間 | 理由 |
   |---|---|---|
   | 紅葉・花の現況ページ | 24時間 | 公式の更新は週1〜2回が多い |
   | 野鳥の観察記録（東京港野鳥公園など） | 24時間 | 毎日〜数日ごとの更新 |
   | 施設の発信（ビジターセンター） | 48時間 | 週1回程度の更新が多い |
   | まつり・行事・観察会 | 7日 | 期間は変わりにくい |
   | 開園時間・アクセスなどの実用情報 | 30日 | ほとんど変わらない |
   | 名所カタログ・知識カード・気象庁の平年 | 取得しない | 質問のたびには読まない |

   情報源の台帳に、更新の曜日が分かっているもの（東京都公園協会の月・木など）は、その日を過ぎたときだけ読み直してよい（任意）。
4. **ページの日付が古くても、有効期間内に読んでいれば読み直さない**。答えには、これまでどおり「○/○時点」（ページの日付）を書く。
5. **現況の情報源がない候補**は、読み直しの対象にしない（読むページがないため）。
6. 1回の質問で読むページの上限を、8 → **3** に下げる（設定値）。上限を超えた分は、キャッシュの古い記録を日付つきで使う。
7. 段階58の「公式ページが分かったら必ず読む」は、「**キャッシュの有効期間を過ぎていれば読む**」に読み替える（CLAUDE.md・スキルの文も直す）。
8. テストを足す（合成データ、通信なし）: 有効期間内なら対象にならない／ページの日付が古くても、昨日読んでいれば対象にならない／期限切れだけが対象になる／上限3件／本文が保存されない。
