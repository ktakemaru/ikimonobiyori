## 1. 第1部: 小さな直し（本人の会話 2026-11-12 から）

1. **旬が日付になる**: 「秩父で見られる花は?」で、宝登山ロウバイ園の時期が「例年は12月21日から2月28日」と出た。記録は「12月下旬〜2月下旬」。資料と答えで、旬の書き方を日付に直さないこと。同じことがほかの名所で起きないか確かめる。
2. **時期の食い違い**: 多々良沼の白鳥が、「野鳥のおすすめ」では「例年11月中旬から3月上旬（最多は1月下旬〜2月上旬）」、「白鳥を見たい」では「城沼と多々良沼は例年1月下旬から3月上旬」と出た。同じ場所・同じ種の例年の時期が、質問によって食い違わないようにする（見られる期間と、数が多い時期を分けて持つ）。ほかの名所にも同じ食い違いがないか、機械で点検し、一覧を報告書に書く。
3. **聞かれていない話**: 「秩父で見られる花は?」の最後に、冬桜の説明と「秩父で冬桜が見られる場所は見つかっていません」が付いた。場所を聞く質問では、その場所の候補にない種の「一般の話」のカードを資料に入れない。
4. **崩れた文**: 境川遊水地の「公式の観察ブログでは活動で13種とされています」。もとの記録の状態の文を調べ、意味の通る形に直す（例: 「10月21日の観察で13種」。原文と照らす）。
5. **途中の文**: その場で調べるあいだに「公式ページを探しています。いまのところ、検索結果に出てくるのは紹介サイトだけです。」が画面に出た。手順書に、調べているあいだも作業の説明を書かないことを明記する（Sonnet で1問試し、途中の文が出ないことを確かめる）。

## 3. 第3部: 写真集め（この段階の中心）

**今ある写真の仕組み**（種ごとのキャッシュ、iNaturalist・Wikimedia Commons、撮影者とライセンスの表示）を使って、写真つきのページで使う写真を先に集めておく。仕組みは変えない（足りないところだけ直す）。

### 3.1 写真の決まり

- **ライセンスが明確なものだけ**。使えるライセンスは、今の仕組みが受け入れているものと同じにする（広げない）。撮影者・ライセンス・元のページの URL を必ず記録する。
- **何の写真かが確かめられるものだけ**。iNaturalist は、種の同定が確かな区分（研究用グレード）の観察に限る。Wikimedia Commons は、ファイルの説明・カテゴリで種や場所が確かめられるものに限る。確かめられないものは使わない。
- **範囲内で撮られた写真を優先**する（撮影地が分かるとき）。なければ国内、それもなければ使わないで「写真なし」と記録する（外国の別亜種・園芸品種の写真で代用しない）。
- 人の顔がはっきり写っている写真、私有地の中の写真、巣・ひな・ねぐらに近づいて撮ったと分かる写真は使わない。希少種は、撮影地が細かく分かる写真を使わない。
- 1つの種につき**最大3枚**（全体の姿・見分けの決め手・季節の姿）。花は、花の時期の写真を必ず1枚。
- 大きさ・保存の形式は、今の仕組みのまま。データ置き場の写真のキャッシュの合計が、開始のときより 300MB を超えて増えないこと。
