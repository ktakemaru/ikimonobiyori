## 第2部: 写真つきのページの確かめ

### 分かったこと(直す前)
- 新しい形(段階77 から既定)の答えは `ask verify --brief` が `logs/last_guide_answer.json` にだけ残し、今までの形の「直前の答え」(`ask/last_answer.json`)・「直前の計画」(`ask/last_plan.json`)を更新しない。
- そのため、新しい形の答えのあとに「写真つきのページにして」→ `ask page` は、**「先に質問してください(直前の答えがないか、24時間より前のものです)」で止まる**(終了コード 2。`ask photos` も同じ)。24 時間以内に今までの形の答えがあれば、**その古い答え・計画のページ(直前の答えと違う内容)ができる**。手書きの HTML で代用される危険もあった。

### 直したこと
- `ask page`・`ask photos` は、直前の答えが新しい形(`last_guide_answer.json` が今までの形の答え・計画より新しい)なら、**合格した最終の文と、その資料(ask brief の作業フォルダの facts.json)から**ページを作る(新しい部品 `ikimonobiyori/guide_answer_page.py`)。今までの形の計画は作り直さない。
  - 本文: 最終の文をそのまま(太字の印 `**` だけ外す)。出典の行の URL はリンクにする。だから同じ場所・同じ順・同じ現況と日付・同じ出典になる。
  - 写真: 文に出る名所の種(facts.json の樹種・花の種類・公園の鳥)と、文に名前の出る種(写真の対応表の和名と、漢字の書き方の対応 `season_place.yaml` の `guide_page.aliases`。出典の節より後ろは見ない)。紅葉の答えで種がひとつも分からないときだけ、代表の木(イロハモミジ・イチョウ)。写真はその場所で撮られたものではない、という注記は今までのページと同じ。
  - 写真がない種は手描きの図にせず「写真が取れなかった種: …」の 1 行。撮影者・ライセンス・状態(開花など)は写真ごとに出る(今までと同じ表示)。
  - キャッシュにない種の写真は確認なしで取りに行く(承認B。上限・間隔・許可ホストは今の方針のまま)。
- `answer_page.build` に、種を呼び出し側が決める・URL をリンクにする、を足した(既定は今までどおり)。
