# 段階54 第8部: 取得した文章への安全対策の点検

## 見つけた箇所と対応
| 箇所 | 状況 | 対応 |
|---|---|---|
| `observations.record` / `validate`（状態・例年の時期・実用情報・名前・発行元） | 状態などは80字で切るが、指示に見える文・制御文字・極端に長い名前を通していた | 方針 `record.untrusted_text`（欄ごとの長さの上限、指示に見える語の一覧）を足し、`untrusted_errors` で記録を拒否する（直した） |
| `guide.record_candidates`（検索で見つけた候補） | 長さの上限はあるが、指示に見える文・制御文字は見ていなかった | `_untrusted_item_errors` で拒否（直した） |
| 写真の退避ファイル名（`guide_photos.archive_rejected`） | 取得したメタの値（photo_id / source）をファイル名に使っていた | 英数字・`_`・`-` 以外を `_` に置き換え、40字まで（直した） |
| 写真のキャッシュのパス | 数値の taxon id だけを使う | 問題なし |
| 子プロセス・シェル | コードに subprocess / os.system はない | 問題なし |
| 通信先ホスト・台帳の承認・設定 | 取得した文字列からこれらを書き換えるコードはない（承認は `guide review` などの明示のコマンドだけ）。テストで、悪意ある入力を渡しても台帳と方針のファイルが変わらないことを確かめた | 問題なし |
| 答えへの流れ | 状態の原文は80字までの引用として出る。検査器（ask verify）は、事実にない日付・数字・URL・場所名を落とす | 記録の段階で指示に見える文を拒否するため、引用にも入らない |

## 直さなかった点
- 指示に見える語の一覧は完全ではない（言い換えは防げない）。一覧は方針に置き、見つけたら足す。決め手は「取得した文章を実行・承認・通信先の追加に使うコードがない」構造であること。
- 状態の原文は引用として答えに出るため、指示に見えない普通の文でも80字までは通る（事実の引用であり、仕様）。
