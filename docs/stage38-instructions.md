## 3. やること（段階38）

main の最新から切る。

### 3-1. 公園と鳥を結びつける

- 各探鳥地（カタログの野鳥の名所）ごとに、「この公園で見られる鳥」の一覧を `facts` が出す。材料は次の順:
  1. **最近の記録**（公園・野鳥の会などのページで読んだ観察の記録。日付と出典つき）
  2. **この時期の記録**（iNaturalist の過去の記録。下の 3-2 の範囲と選び方）
  3. 前の年の同じ時期の記録（読んだもの）
- 鳥ごとに: 和名・材料の種類（最近の記録／この時期の記録）・日付または集計の期間・出典・**なぜ今か**の一言（冬鳥が来始める、最近の記録あり、など。材料から決まった文で作る）・写真があればその写真の情報（3-4）。
- 文章の答えと HTML は、**同じ `facts`** から作る。

### 3-2. 「この時期に見られる鳥」の選び方と範囲

- **範囲**: 半径10kmの円をやめ、探鳥地ごとの範囲にする。カタログに範囲（中心と半径、または緯度経度の四角）を持たせ、既定は半径2km（値は方針ファイルに置き、出典か「仮置き」を書く）。海岸から離れた内陸の名所で、海の鳥（カモメ類・ウミネコ・イソヒヨドリ・ウミウなど）が上位に来るなら、範囲が広すぎる合図として報告書に書く。
- **選び方**: 記録の多い順をやめ、**季節らしさ**で並べる。例: その時期（対象の日の前後1週間）の記録の割合が、その場所の一年の平均の割合より大きい鳥を上に（式と値は方針ファイルに。出典か「仮置き」）。一年中多い鳥（トビ・ヒヨドリ・ハシブトガラスなど）は、季節らしさが低ければ後ろに回す（消さない）。最近の記録にある鳥は、季節らしさより先に出す。
- 集計は、2-1 の仕組みで、古ければ質問のときに自分で取り直す（7日より古いか、対象の日が前回の集計の期間の外）。
- 位置の丸め（絶対ルール7）・観察者や正確な座標を出さない規則は変えない。

### 3-3. 写真つきの公園ページ

- `python -X utf8 -m ikimonobiyori.guide page` を広げる（または新しいコマンド）。**公園ごとの節**に、その公園の鳥を写真つきで並べる。各鳥: 写真（無ければ「写真なし」）・和名・なぜ今か・材料の日付と出典。写真には撮影者名・ライセンスを表示し、iNaturalist（または Commons）の写真のページへリンクする。
- 各公園の節に、対象の日の開園・休み（`closures`）、最近の記録の日付、公園のページへのリンクを添える。
- ページに1回だけ、「写真は種の代表写真で、その公園で撮られたものではありません」と書く。
- 写真がまだ手元にない鳥は、2-1 の仕組みで、その場で取りに行く（上限の範囲。足りなければ「写真なし」で出し、止めない）。
- 1枚の HTML で、手元のブラウザで開ける（写真はページの横のフォルダか埋め込み。どちらでもよいが、ページを開いて写真が出ること）。スマホの幅でも崩れない。
- 置き場所は書き込み先の下（`%LOCALAPPDATA%\ikimonobiyori\guide\pages\`）。**写真・画像・撮影者名・写真の URL はコミットしない**（既存の規則）。
- ページの文も、文章の答えと同じ検査（`verify`）を通す。

### 3-4. スキル `ikimono-weekend` の手順

- 「HTMLにして」「ページにして」「写真つきで」と頼まれたら、答えの手順（`prepare` → 読む → `record` → `facts` → 答え → `verify`）のあと、3-3 のページを作り、`--open` で開く。
- **利用者への最後の返事は、検査を通った答えの本文と、ページの場所の1行だけ**にする。「今回の作業で実行したこと」「テスト」「コード」「リポジトリ」「追跡ファイル」「保存先」など、作業・開発の説明を書かない。スキルの本文にこれを明記し、`verify` に「返事の全文」を渡して検査できるようにする（答えの本文の外に付け足した文も落とす）。
- 硬い言い回しを減らす: 「公式ではない」は補足に1回まとめる（各行では「tenki.jp」など出典名だけ）。「例年の時期は分かりません（今年の行事「○○」は○/○〜○/○）」のように、同じ期間を2度書かない（「例年の時期は分かりません。今年は○/○〜○/○に○○があります。」）。検査器が許す言い方をそれに合わせる。

### 3-5. テスト（合成データ。通信しない）

1. 自前の上限: 上限で止まる、間隔を守る、記録が残る、許可外のホストを拒否する。ハブの計測フックがあるときはそちらを使う。
2. 範囲: 探鳥地ごとの範囲で集計される。既定の半径が方針ファイルの値。
3. 季節らしさ: 一年中多い鳥が、季節らしい鳥より後ろに来る。最近の記録の鳥が先に来る。
4. 公園ページ: 公園ごとの節に、その公園の鳥だけが写真つきで出る。写真がない鳥は「写真なし」。撮影者名・ライセンス・写真のページへのリンク・「種の代表写真」の1文がある。開園・休みがある。
5. 返事の全文の検査: 作業・開発の説明が落ちる。
6. 既存のテストがすべて通る。
