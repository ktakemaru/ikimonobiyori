### 6-2. 原因と直し方
実通信ではなく、**大きい YAML を `yaml.safe_load`(PyYAML の純 Python 版)で何百回も読み直していた**こと(1 回 約 0.35 秒)。
- `wildflower.sites_by_id()`(`data/sites.yaml`)が、1 回の `overview` で 365 回読まれていた。
- `guide.load_policy()`(202 回)・`observations.load_policy()`(159 回)・`guide.committed_entries()`(57 回)・`catalog.load_catalog()` も同じ。
直し: 小さな入れ物 `ikimonobiyori/yamlcache.py`(パス・更新時刻・大きさごとに 1 回だけ読み、呼ぶたびに `deepcopy` を返す。ファイルが変わると読み直す)を作り、上の読み込みをこれ経由にした。
- 出力が同じことの確認: `wildflower.overview(month=11)` の出力を、直す前に保存し、直した後と JSON で比べて一致(直す前 約 57 秒 → 直した後 約 1 秒)。
- 既存テストの期待値・ゴールデンは変えていない。新規テスト 15 件(`tests/test_stage46.py`)を足した。

**合計 388.0 秒(約 6.5 分)、1083 件(1068 + 新規 15)、失敗 0、エラー 0**(`Ran` / `OK`)。変更前の約 5 分の 1。遅い順の上位は 9.0 秒以下(最大 test_stage43.Zukan.test_overflow_goes_to_a_second_page_of_the_same_season)。モジュールの合計は test_stage38 47 秒・test_stage31 41 秒・test_stage29_page 30 秒・test_stage36 28 秒。
